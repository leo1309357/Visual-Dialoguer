01 · 简介

CDLG 是什么

CDLG(Conversations Dialogue Script)是 Eraphanis 工程里驱动游戏对话的脚本语言。对话以脚本块的形式写在 .cdlg 文本文件里,由 libs/cdlg 解析器读取,交给 Session 运行时驱动 NPC 对话、分支选项与剧情跳转。

一个对话脚本由三样东西组成:

  1. 脚本块(dialogue)——一段完整对话的容器,有自己的 id;
  2. 节点(node)——一串按顺序执行的指令,是对话的"场景单元";
  3. 指令(instruction)——最小动作,例如"某人说了一句话"、"给出一个选项"、"跳去某个节点"。

脚本内所有跳转都以节点 id 为目标。结构是树状的,数据流是跳转驱动的。

VisualDialoguer 的角色

VisualDialoguer 是 CDLG 的可视化编辑器(Windows 桌面程序,C# / WinUI 3):

  • 把 .cdlg 文本解析成结构化的节点 / 指令模型,以三栏工作台(节点 / 指令 / 属性)编辑;
  • 提供流程图覆盖层,把节点与 goto / choice 连线画成规则网格;
  • 提供校验(F5)与解析报告,在保存前拦住结构错误;
  • 写出的文件与 libs/cdlg 解析器、Session 运行时直接兼容。
.cdlg 文本 ──解析──▶ 内存模型 ──编辑──▶ 内存模型 ──序列化──▶ .cdlg 文本
                        ▲                                    │
                        └────────── 校验 / 流程图 ◀───────────┘

设计目标

  • 人类可读:CDLG 是行式文本,缩进表达层级,# 写注释,任何文本编辑器都能改;
  • 机器可靠:三级缩进规则严格,序列化输出与解析器约定完全一致,写出的文件必然能读回;
  • 可脚本化:整个对话是纯文本,可以放进版本控制、做 diff、参与自动化流程;
  • 编辑器友好:结构规整,适合可视化的节点—连线呈现。

与 Eraphanis 工程的关系

  • 语法与缩进规范与 libs/cdlg 解析器(Parser.cpp)保持一致;
  • 编辑器写出的转义、缩进、选项分隔符(归一化为 ->)是解析器的合法输入;
  • 结构校验规则与 libs/cdlg/src/Parser.cpp 的检查一致(入口存在、id 不重复、节点非空壳、跳转目标存在)。
VisualDialoguer 项目本身已从 Eraphanis 仓库独立出来,不共享任何构建;两者只通过 .cdlg 文本这一种格式交互。

支持范围

  • 编辑器只编辑每个文件里的首个 dialogue 块;文件里其余块会被原样保留,保存时写回(详见 08 · 常见问题);
  • 流程图是按节点顺序计算的规则网格,不支持手动拖动布局;
  • 文本格式:序列化输出 UTF-8 无 BOM、LF 换行;解析时 BOM、CRLF、\r 都能容忍。

02 · 快速开始

1. 准备一个 .cdlg 文件

用任何文本编辑器创建 hello.cdlg,内容如下(缩进 2 或 4 空格均可,但层级必须正确,见 03 · 格式与语法):

dialogue opening
  entry start
  node start
    speaker 旅店老板
    line 欢迎来到云雾镇,旅行者。
    choice 打听传闻 -> rumor
    choice 直接出发 -> leave
  end
  node rumor
    line 据说北边的古堡最近闹鬼。
    goto leave
  end
  node leave
    line 一路小心。
    end
end

保存文件(UTF-8 编码即可;编辑器对 BOM、CRLF 都宽容)。

2. 用 VisualDialoguer 打开

启动编辑器,点工具栏 打开 按钮(或 Ctrl+O),选择 hello.cdlg。

  • 左侧节点栏出现三个节点:start、rumor、leave;
  • 左侧第一个节点自动被选中,中栏显示它的指令列表;
  • 状态栏显示:节点数、指令数、撤销 / 重做深度。

3. 浏览与编辑

  • 点中栏任意指令,右侧属性面板显示该指令的字段,直接改;
  • 点左侧节点栏下方的 ＋ 新建节点;点 ★ 把选中节点设为入口;
  • 在节点内选中指令后,可用中栏的 上移 / 下移 调整顺序,或 删除;
  • 所有改动实时反映到状态栏的未保存标记(标题前的 *)。

4. 校验

按 F5(或工具栏 校验 按钮)运行结构校验:

  • 校验通过:状态栏显示"校验通过:没有发现问题。";
  • 发现问题:弹出校验报告,逐条列出(如"入口节点 'x' 不存在")。

校验规则完整清单见 04 · 指令类型与字段 与 05 · 节点与入口。

5. 看流程图

按 Ctrl+F(或工具栏 流程图 按钮)打开流程图覆盖层:

  • 每个节点是一张索引卡,卡片左侧的书脊颜色取自该节点第一条指令的语义色;
  • 入口节点卡片的书脊与标题用签名色,并带 ★ 前缀;
  • choice / goto 指令画成卡片之间的牵线,带箭头;choice 的选项文本做成压在连线中点的小纸片;
  • 点某张卡片,覆盖层关闭,工作台选中该节点。

6. 保存

按 Ctrl+S 保存。若文件还没存过盘,会弹出保存对话框,默认文件名是脚本 id + .cdlg。

编辑器保存时输出 UTF-8 无 BOM、LF 换行的文本——Eraphanis 的 libs/cdlg 解析器可以直接加载。

03 · 格式与语法

CDLG 是行式、缩进敏感的文本格式。本章给出完整语法参考,全部规则与 VisualDialoguer.Core 的解析器(CdlgFormat.Parse)一一对应。

3.1 块结构

一个 .cdlg 文件可以包含一个或多个 dialogue 块。每个块是:

dialogue <id>          ← 脚本块开始(缩进 0)
  entry <node-id>      ← 入口节点(缩进 2,可选)
  node <node-id>       ← 节点开始(缩进 2)
    指令...            ← 指令(缩进 4)
  end                  ← 节点块结束(缩进 2)
end                    ← 脚本块结束(缩进 0)
层级加权宽度允许的命令
0(顶层)indentWidth == 0dialogue <id>、end
1(脚本块内)1 ≤ indentWidth ≤ 2entry <id>、node <id>、end
2(节点块内)indentWidth ≥ 38 种指令(见 04)
层级由"加权宽度"决定,不是由空格个数直接决定:每个空格权重 1,每个 Tab 权重 2(因为 cdlg 一级缩进就是 2 空格,一个 Tab 顶一级)。所以: - 2 空格 → 层级 1;4 空格 → 层级 2; - 1 个 Tab → 层级 1;2 个 Tab → 层级 2; - 缩进宽度 3 及以上(无论怎么凑)一律按层级 2 处理。 空格与 Tab 可以混用,只要"加权宽度"落在正确区间。层级错了,命令就放错了位置,解析器会报"命令出现在 dialogue/node 块之外"。

3.2 语法单元

dialogue 块

  • dialogue <id>:开始一个脚本块,<id> 是该脚本的标识,缺 id 报错;
  • 块内依次可以有 entry 与任意多个 node;
  • 顶层 end:结束当前脚本块(解析器此刻清空"当前脚本/当前节点"上下文);
  • 一个文件多个 dialogue 块依次解析,依次序列化。

entry 与 node

  • entry <node-id>:声明入口节点。缺 id 报错。入口节点必须真实存在,否则校验不过(见 05);
  • node <node-id>:开始一个节点。缺 id 报错;
  • 层级 1 的 end:结束当前节点块。

指令行

  • 层级 2 的行是一条指令;
  • 指令必须出现在节点块内,否则报"指令 'x' 出现在 node 块之外";
  • 指令末尾的 end:结束当前节点块(相当于"对话到这里结束")。

3.3 注释与空白

解析器对空白与注释非常宽容:

  • 注释:一行的正文(去掉缩进后)以 # 开头,整行跳过;
  • 空行:跳过;
  • BOM:文件开头的单个 U+FEFF 字符被跳过(注意只跳一个字符,不会误吃正文);
  • 换行:\r\n、单独 \r 都会先归一化为 \n 再按行切分;
  • 行尾空白:每行正文会去掉行尾的空格与 Tab。

3.4 命令与参数的拆分

  • 命令名是行首第一个空白(空格或 Tab)之前的部分;
  • 参数是命令名之后、去掉首尾空白的剩余文本;
  • set / emit 用首词拆分:第一个词是键 / 信号 id,剩余部分是值 / payload。

3.5 转义

指令的参数(说话人、台词、选项标签、set 值、emit payload)支持转义,序列化与解析双向往返:

转义序列含义
\n换行
\t制表符
\r回车
\\反斜杠本身
\"双引号
  • 未知转义(如 \x)解析时保留反斜杠原样(\x 两个字符都保留);
  • 转义是按字符处理的,不限于特定字段——speaker、line、choice 标签、set 值、emit payload 都走同一套转义;
  • goto / choice 的目标节点 id、set / clear 的标志名、emit 的信号 id 不转义(它们是按词切分的标识符,含空白就切碎了)。

3.6 choice 的选项分隔符

choice 指令用一个分隔符把"选项标签"与"目标节点"切开。解析器两种写法都接受:

choice 打听传闻 -> rumor     ← 首选写法(序列化时归一化为这种)
choice 打听传闻 | rumor      ← 兼容写法(解析也接受)
  • 解析顺序:先找 ->,找不到再找 |;
  • 标签与目标都会 Trim;
  • 标签与目标都非空才有效;
  • 序列化统一输出 -> ;
  • 反过来,标签本身不能包含 -> 或 |——校验器会拦住(否则保存后读不回)。

3.7 序列化输出规范

编辑器保存(Ctrl+S)时,按以下规范输出文本:

  • 编码:UTF-8,无 BOM;
  • 换行:LF(\n);
  • 缩进:dialogue 与顶层 end 缩进 0;entry、node 与节点块 end 缩进 2;指令缩进 4;
  • 字段:speaker / line / choice 标签 / set 值 / emit payload 均做转义;choice 分隔符归一化为 ->;
  • 脚本 id 为空时,序列化为 dialogue untitled;
  • entry 为空时不输出该行;
  • 指令按内存顺序逐条输出;emit 的 payload 为空时不输出空格与 payload。

3.8 完整示例

一个带注释、多节点、多指令的合法脚本:

# 开场对话 —— 注释可以写在任何层级
dialogue opening
  entry start
  node start
    speaker 旅店老板
    line 欢迎来到云雾镇。
    choice 打听传闻 -> rumor
    choice 直接出发 -> leave
  end
  node rumor
    line 据说古堡闹鬼。
    set rumor_heard yes
    goto leave
  end
  node leave
    line 一路小心。
    end
end

04 · 指令类型与字段

CDLG 共 8 种指令,类型顺序固定(与 cdlg::InstructionKind 一致,编辑器的类型下拉框也按这个顺序排):

#关键字显示名徽章语法
0speaker说话人 speaker说speaker <name>
1line台词 line词line <text>
2choice选项 choice选choice <label> -> <node>
3goto跳转 goto跳goto <node>
4set置标志 set置set <flag> <value>
5clear清标志 clear清clear <flag>
6emit发信号 emit信emit <signal> [payload]
7end结束 end止end

徽章是界面(指令列表、流程图)使用的单字语义标记。

4.1 speaker — 说话人

设置当前说话人,影响后续 line 的归属。

speaker 旅店老板
speaker Narrator
字段名称说明
Speaker说话人必填;转义字段,支持 \n 等

校验:speaker 指令的说话人为空 → 节点 'x' 的 speaker 指令缺少说话人。

4.2 line — 台词

输出一句台词。

line 欢迎来到云雾镇,旅行者。
line 你可以选择:\n1. 打听\n2. 离开
字段名称说明
Text文本必填;转义字段

校验:line 指令的文本为空 → 节点 'x' 的 line 指令缺少台词文本。

4.3 choice — 选项

给玩家一个分支选项,选中后跳转到目标节点。

choice 打听传闻 -> rumor
choice 直接出发 | leave        ← 解析也接受 | 分隔
字段名称说明
Text选项文本必填;转义字段;**不能包含 -> 或 ``**
TargetNode目标节点必填;必须指向存在的节点

校验:

  • 选项文本为空 → 节点 'x' 的 choice 选项标签不能为空;
  • 标签包含 -> 或 | → 节点 'x' 的 choice 标签不能包含分隔符 '->' 或 '|'(保存后读不回);
  • 目标节点为空 → 节点 'x' 的指令缺少目标节点;
  • 目标节点不存在 → 节点 'x' 引用了不存在的节点 'y'。

4.4 goto — 跳转

无条件跳转到目标节点,当前节点到此中断。

goto leave
字段名称说明
TargetNode目标节点必填;必须指向存在的节点

校验:同 choice 的目标节点规则(缺目标 / 目标不存在都报错)。

4.5 set — 置标志

把对话标志(flag)设为一个值。常用于记录剧情状态。

set rumor_heard yes
set gold 100
字段名称说明
FlagKey标志键必填;标识符:非空白、不含空白字符、不能以 # 开头
FlagValue标志值必填;转义字段

校验:

  • 键或值为空 → 节点 'x' 的 set 指令需要 <标志> <值>;
  • 键不合法(见下)→ 节点 'x' 的标志名 '...' 不能包含空白字符 / 不能以 '#' 开头。

4.6 clear — 清标志

清除一个对话标志。

clear rumor_heard
字段名称说明
FlagKey标志键必填;标识符规则同 set

校验:

  • 标志名为空 → 节点 'x' 的 clear 指令缺少标志名;
  • 键不合法 → 同上。

4.7 emit — 发信号

发出一个游戏信号,可带可选载荷(payload)。用于向游戏运行时广播事件(播放音效、触发演出等),具体语义由 Session 运行时决定。

emit sfx_door
emit quest_started 古堡之谜
字段名称说明
SignalId信号 ID必填;标识符:非空白、不含空白字符、不能以 # 开头
SignalPayload信号载荷可选;为空时序列化不输出;转义字段

校验:

  • 信号 id 为空 → 节点 'x' 的 emit 指令缺少信号 id;
  • 信号 id 不合法 → 节点 'x' 的信号 id '...' 不能包含空白字符 等。

4.8 end — 结束

结束当前节点块(对话到此结束)。注意:节点块 end 缩进 2,指令 end 缩进 4,二者是不同层级的东西(见 03 · 格式与语法)。

end

无字段,无专项校验。

4.9 标识符规则(flag / signal / 节点 id 通用)

set / clear 的标志键、emit 的信号 id、节点 id、目标节点引用都按"按词切分的标识符"处理,共享同一套合法性规则:

  1. 不能为空串(各字段的必填检查单独负责报错);
  2. 不能只含空白字符 → ... 只含空白字符;
  3. 不能以 # 开头(会被解析器当注释吃掉)→ ... 不能以 '#' 开头(会被当作注释);
  4. 不能包含任何空白字符(空格 / Tab / 换行)→ ... 不能包含空白字符。
直观理解:这类字段在行内是"一个词",含空白就切碎了;以 # 开头则整行变成注释。speaker 的人名、line 的台词、choice 的标签、set 的值、emit 的载荷不受此限(它们可以含空格,用转义处理特殊字符)。

4.10 切换指令类型时的字段清理

在编辑器里把一条指令改成另一种类型时,原来类型的字段会被清空,避免"存出去一半旧一半新":

切换后类型保留的字段被清空的字段
speakerSpeaker其余全部
lineText其余全部
choiceText、TargetNode其余全部
gotoTargetNode其余全部
setFlagKey、FlagValue其余全部
clearFlagKey其余全部
emitSignalId、SignalPayload其余全部
end无其余全部

05 · 节点与入口

5.1 节点是什么

node 是对话的"场景单元":一串按顺序执行的指令。运行时从入口节点开始,顺序执行每条指令,遇到 choice 等待玩家选择后跳转,遇到 goto 无条件跳转,遇到指令 end 则本段对话结束。

node start
  speaker 旅店老板
  line 欢迎来到云雾镇。
  choice 打听传闻 -> rumor
  choice 直接出发 -> leave
end

节点有三个属性:唯一 id、指令列表、以及"是否入口"。

5.2 节点 id 规则

  • 节点 id 是脚本内的唯一标识,goto / choice 全部靠它寻址;
  • 合法 id 必须满足标识符规则(见 04 · 4.9):
  • 非空;
  • 不含空白字符(空格 / Tab / 换行);
  • 不以 # 开头;
  • 大小写敏感(start ≠ Start),字符串比较为 Ordinal。

校验:

  • 节点 id 重复 → 节点 id 重复:'x'(两两比对,每对重复都报一次);
  • id 不合法 → 按标识符规则报错。

5.3 入口节点(entry)

每个脚本块可以声明一个入口节点,用 entry 指明。运行时从入口节点开始执行对话。

dialogue opening
  entry start        ← 入口
  node start
  ...
end

规则:

  • entry 可选;不写也行(序列化时不输出该行);
  • 但一旦写了,目标节点必须存在;
  • 校验:
  • 缺少入口 → 缺少入口节点(entry)定义;
  • 入口指向不存在的节点 → 入口节点 'x' 不存在;
  • 入口 id 不合法 → 按标识符规则报错。

5.4 引用语义:goto / choice

goto 与 choice 的 TargetNode 是强引用——脚本里引用的目标必须在同一脚本块内真实存在:

  • 目标为空 → 节点 'x' 的指令缺少目标节点;
  • 目标不存在 → 节点 'x' 引用了不存在的节点 'y';
  • 目标 id 不合法 → 按标识符规则报错。
编辑器不会自动"补"缺失的节点;校验的作用就是让你在保存前发现断链。流程图里指向不存在目标的连线画不出来(渲染时直接跳过),校验报告会告诉你。

5.5 节点不能是空壳

每个节点至少要有一条指令:

  • 节点没有任何指令 → 节点 'x' 没有任何指令。
新建的节点默认是空壳;在校验通过前,记得给它加指令。

5.6 自动命名与重命名

  • 自动命名:编辑器新建节点时,自动生成 node1、node2…(前缀 + 递增数字,直到不重复为止);默认前缀 node。
  • 重命名:在编辑器里重命名节点 id 时,所有引用会同步更新:
  • 该节点的 id;
  • 所有指令里指向旧 id 的 TargetNode(goto / choice);
  • 脚本的 EntryNodeId(若入口是它);
  • 当前选中项(若选中的是它)。
  • 若新 id 已被占用,重命名被拒绝并返回失败。

5.7 粘贴节点

复制 / 粘贴节点时,粘贴出的节点 id 在原 id 后加 -copy 去重:冲突时依次尝试 -copy-2、-copy-3… 直到不重复。注意:粘贴的是节点的浅拷贝语义——指令原样复制,但 goto / choice 的目标引用不会改写(指向谁仍指向谁,不因粘贴而重定向)。

5.8 多 dialogue 块

一个文件可以含多个 dialogue 块。编辑器只编辑首个块:解析时全部块都进模型,但界面只暴露第一个;保存时其余块原样写回(不经过编辑器的序列化逻辑,保持字节语义)。

因此:如果你的 .cdlg 文件里有多段对话,请把需要编辑的那段放在文件最前面。界面不提供切换块的入口(见 08 · 常见问题)。

5.9 删除节点

删除节点时:

  • 节点从脚本中移除;
  • 若删除的是入口节点,入口定义一并清空(避免留下悬空入口);
  • 选中项自动移到相邻节点(优先原位置的下一个)。

07 · 原理

本章讲 VisualDialoguer 内部是如何工作的。源码按职责分三层:

VisualDialoguer.Core   模型 / 解析 / 序列化 / 编辑状态(不依赖 UI)
VisualDialoguer.Theme  Loma 主题库(独立 WinUI 类库)
VisualDialoguer.App    界面(主窗口 / 工作台 / 流程图 / 属性面板)

7.1 解析原理(CdlgFormat.Parse)

解析器把 .cdlg 文本变成内存模型(List<DialogueScript>),并按行收集解析问题。

预处理

  1. 若开头是 U+FEFF(BOM),只跳这一个字符(U+FEFF 是一个字符不是三个字节,跳三个会把正文头两个字吃掉);
  2. 把 \r\n 与单独 \r 全部归一化为 \n,再按 \n 切行。

逐行切分

每一行计算两个数:

  • whitespaceCount:前导空白字符数(用来切掉缩进拿到正文);
  • indentWidth:加权宽度——空格 +1,Tab +2。这是为了把 Tab 正确折算进层级(一级缩进 = 2 空格,一个 Tab 顶一级)。

然后:

  • 去掉行尾空白;
  • 正文为空或以 # 开头 → 跳过(注释与空行);
  • 按加权宽度算层级:0 → 层级 0,1~2 → 层级 1,3+ → 层级 2。

状态机

解析器只维护两个状态:当前脚本(current)与当前节点(currentNode),按层级分派:

层级命令行为
0dialogue <id>建脚本,加入列表,重置节点上下文
0end关闭当前脚本(清空两个状态)
1entry <id>写 EntryNodeId
1node <id>建节点并追加到当前脚本
1end关闭当前节点
28 种指令追加指令(命令名由首个空白切出,参数 Trim)

参数解析细节:

  • speaker / line:整段参数 Unescape;
  • choice:先找 ->,再找 |,切出标签与目标,两边 Trim,标签与目标都非空才有效;
  • set:首词拆键,剩余为值;
  • emit:首词拆信号 id,剩余为可选 payload;
  • 每条指令都做必填检查,缺了就记一条 FormatIssue(行号, 消息)。

宽容但认得同一套语法

解析器对空白形态宽容(BOM、CRLF、Tab、空行、注释),但对结构严格(层级错、命令错都报行号)。这样设计让"人写的"和"编辑器写的"文件都能读进来,同时坏结构不会静默产生错误模型。

7.2 序列化原理(CdlgFormat.Serialize)

序列化是解析的逆过程,逐脚本、逐节点、逐指令写出,严格对齐解析器约定:

  • 脚本 id 为空 → dialogue untitled;
  • entry 为空 → 不输出;
  • 节点:缩进 2 的 node <id>;
  • 指令:缩进 4;speaker / line / choice 标签 / set 值 / emit payload 走 Escape;
  • choice 分隔符归一化为 -> ;
  • 节点块 end 缩进 2,脚本块 end 缩进 0;
  • 多脚本块依次写出。

编码:UTF-8 无 BOM + LF,由 App 层 SaveFileAsync 负责写入(new UTF8Encoding(false))。

7.3 校验原理(DialogueModel.Validate)

Validate 返回字符串列表,空列表 = 通过。检查顺序:

  1. 入口:缺失 → 报;指向不存在 → 报;
  2. 标识符:脚本 id、入口 id、每个节点 id、goto/choice 目标、set/clear 标志键、emit 信号 id 都过 CheckIdentifier(非空白、不含空白、不以 # 开头;空值不报,由专项检查管);
  3. id 唯一:节点两两比对,每对重复报一次;
  4. 空壳:节点指令数为 0 → 报;
  5. 引用:goto/choice 目标空或不存在 → 报;
  6. 必填字段:speaker 缺说话人、line 缺文本、choice 标签空、choice 标签含 ->/|、set 缺键值、clear 缺标志名、emit 缺信号 id → 各报各的。

校验不改模型,是纯只读检查;编辑器在 F5 时调用,保存前不会自动拦截(保存始终允许,校验是提示性质的)。

7.4 编辑状态原理(EditorDocument)

EditorDocument 是编辑器的状态层,不碰任何 UI;界面把命令翻译成它的调用,它通过 Changed 事件通知 UI 刷新。

脏标记是"比对出来的"

IsDirty 不是"改过就置位"的布尔,而是:

IsDirty = _savedText != CurrentText
CurrentText = CdlgFormat.Serialize(_scripts)

把当前模型序列化出来与上次保存(或新建/载入)的基准比对。好处:改完又撤销回去,内容与磁盘一致时不显示未保存,不会误报。

快照式撤销/重做

  • 每次变更前 BeginChange():把当前状态(整份深拷贝)压入撤销栈,清空重做栈;
  • 容量 MaxHistory = 50,超限丢最旧的;
  • Undo:当前状态压入重做栈,恢复栈顶快照;Redo 反之;
  • 快照包含:全部脚本(每层 Clone)、选中节点、选中指令下标;
  • 选整份快照而不是增量补丁:脚本量级小(几十个节点),简单、无"撤销回一半"的中间态。

属性编辑的特殊撤销策略

属性面板逐键输入不入栈(会让撤销栈被一串单字符淹没)。做法:

  • 字段获得焦点时 CaptureState() 取快照;
  • 失焦且确有改动时,PushUndoState 把该快照压栈。

引用同步

  • RenameNode(old,new):同步更新节点 id、所有 TargetNode、EntryNodeId、选中项;新 id 被占用则拒绝;
  • DeleteSelectedNode:删除节点;若删的是入口,入口定义一并清空;
  • PasteNode:副本 id = 原 id + -copy,冲突时 -copy-2…;引用不重定向;
  • SetSelectedInstructionKind:切换类型时调用 ClearIrrelevantFields 清空无关字段。

多 dialogue 块

  • 解析出的全部块都存进 _scripts;
  • Script 属性返回 _scripts[0](界面只编辑首个);
  • Scripts 属性返回全部;保存时 Serialize(_scripts) 原样写回所有块。

7.5 命令中枢

所有界面动作(工具栏、快捷键)汇入一个命令枚举 EditorCommandId,数值与旧 Win32 cdlg-editor 的命令表一致:

区间命令

7.6 流程图渲染原理(GraphPage)

流程图是代码逐笔绘制(不是 XAML 模板绑定),每次刷新清空画布重画。

布局

  • 固定参数:卡宽 168、卡高 62、列间距 96、行间距 56、3 列;
  • 节点按列表顺序填充:列 = index % 3,行 = index / 3;
  • 画布尺寸:宽 = max(800, 3 × (卡宽+间距)),高 = max(480, 行数 × (卡高+间距));
  • 空脚本也铺出案垫与网格,不是白屏。

绘制顺序(层次自下而上)

  1. 案垫背景(LomaGraphDesk)+ 网格(LomaGraphGrid,32px 间距的细线);
  2. 牵线:遍历每个节点的指令,choice / goto 画连线——源卡右侧中点 → 目标卡左侧中点,1.5px 细线,终点张开三角箭头;目标不存在的边跳过;
  3. 索引卡:三层柔影(环境影 / 左上受光高光 / 关键影)→ 卡面(浮起渐变 + 发丝边)→ 书脊(入口用签名色,否则取节点第一条指令的语义色,空节点退回发丝边色)→ 标题与" N 条指令";
  4. 连线标签:choice 显示选项文本,goto 显示 goto;标签先 Measure 量出真实尺寸再居中,压在连线中点的小纸片(带柔影)上,长短标签都居中。

主题与重画

  • 所有颜色经 Theme.Brush("LomaXxx", fallback) 从 Loma 主题读,不写死颜色;
  • 代码画笔画刷是"重画那一刻"取的,主题切换后必须重画一次——Theme.Changed += Refresh 保证深/浅色切换立即生效;
  • 主题键万一缺失,退回内置兜底色(透明 / 发丝灰 / 墨灰 / 纸色),保证图仍可读而不崩溃。

7.7 主题系统(Loma.Theme)

  • Loma 是独立 WinUI 类库,资源字典 Themes/Loma.xaml;App 通过 ms-appx:///Loma.Theme/Themes/Loma.xaml 合并;
  • 视图样式键:LomaCard / LomaButton / LomaIconButton / LomaWell / LomaSectionTitle / LomaNodeRow / LomaInstructionRow / LomaPadCard 等;
  • 调色板键:LomaBase / LomaInk(系列)/ LomaAccent / LomaSunken / LomaEdge / LomaShadow* / LomaGraphDesk / LomaGraphGrid / LomaThread 等;
  • 标题栏颜色也读 Loma(Theme.Swatch),深浅色切换时跟随;
  • 主题库支持微交互动画(TranslateTransform + CubicEase / QuadraticEase)与桌面顶光渐变背景(LomaDeskGradient)。

7.8 文件读写

  • 打开:FileOpenPicker(.cdlg / .txt)→ 读字节 → new UTF8Encoding(false).GetString(bytes)(兼容无/有 BOM)→ TrimStart('\uFEFF') → Parse;
  • 保存:Serialize → UTF-8 无 BOM 字节 → 截断原文件 → 写入 → MarkSaved;
  • 保存成功才更新 FilePath 与脏基准;失败则状态栏报错,不破坏原文件。

08 · 常见问题

兼容性

编辑器写出的文件,游戏引擎能直接加载吗?

能。序列化严格对齐 libs/cdlg 解析器约定:

  • 缩进:dialogue / 顶层 end = 0;entry / node / 节点块 end = 2;指令 = 4;
  • 选项分隔符归一化为 -> ;
  • 转义序列 \n \t \r \\ \" 双向往返,未知 \x 保留反斜杠;
  • 编码 UTF-8 无 BOM + LF。

打开兼容哪些格式?

.cdlg 与 .txt。解析宽容:BOM、# 注释、空行、CRLF 都能吃;Tab 按加权宽度折算进缩进层级(1 Tab = 2 空格)。

结构校验与引擎一致吗?

一致。校验规则与 libs/cdlg/src/Parser.cpp 的检查对齐:入口存在、节点 id 唯一、节点非空壳、goto/choice 目标存在;编辑器还额外提示各指令的必填字段。

已知限制

为什么编辑器只编辑文件里的第一个 dialogue 块?

设计如此。解析时所有块都进模型,但界面只暴露首个块;其余块在保存时原样写回(不经过编辑器的序列化逻辑)。界面目前不提供切换块的入口。

需要编辑多段对话时,把目标块放在文件最前面。

流程图能手动拖动布局吗?

不能。流程图是按节点顺序算出来的规则网格(3 列),脚本一改图就重画,保证图和脚本永远一致。需要手动布局请改脚本顺序。

choice 标签里能写 "->" 或 "|" 吗?

不能。-> 与 | 都是解析器的选项分隔符,标签里含它们会切不出目标节点。校验器会拦下:choice 标签不能包含分隔符 '->' 或 '|'。

节点 id / 标志名 / 信号 id 能含空格或以 # 开头吗?

不能。它们是按词切分的标识符:含空白会被切碎,以 # 开头会被当注释。校验器会拦下。

为什么不能撤销到"没改之前"的每一步?

撤销栈容量 50 层(超出丢最旧),且属性面板逐键输入不入栈(取快照、失焦才入栈),避免撤销栈被单字符记录淹没。这属于预期行为。

排错

打开文件提示"这个文件里没有 dialogue 块。"

文件里没有合法的 dialogue <id> 行。检查:首行是否为 dialogue <id>(缩进 0),或文件是否为空/全注释。

打开文件提示"已载入,但解析报了 N 个问题"

文件读进来了,但有解析问题(如缩进层级错、命令拼错、缺参数)。按 F5 查看逐行详情,每条都带行号。

F5 校验报"入口节点 'x' 不存在"

entry x 指向的节点不存在。可能:节点被删了,或 id 拼写不一致(大小写敏感)。在节点栏加回该节点,或把 entry 改指向存在的节点。

F5 校验报"节点 'x' 引用了不存在的节点 'y'"

某个 goto / choice 指向不存在的节点。删除该指令,或补建节点 y。注意:流程图里这种连线画不出来,可借此定位。

校验报"节点 'x' 没有任何指令"

节点是空壳。给它加至少一条指令,或删除该节点。

保存后文件打不开 / 引擎报错

  • 确认没有把非法内容写进标识符字段(含空白 / # 开头 / choice 标签含分隔符)——这些在保存前会被 F5 拦下;
  • 确认文件编码为 UTF-8(无 BOM 即可);
  • 确认缩进层级没有错位。

撤销栈深度总是 0?

新建 / 载入会清空历史;若刚打开文件还没做过改动,撤销栈自然是空的。
