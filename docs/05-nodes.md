# 05 · 节点与入口

## 5.1 节点是什么

`node` 是对话的"场景单元":一串**按顺序执行**的指令。运行时从入口节点开始,顺序执行每条指令,遇到 `choice` 等待玩家选择后跳转,遇到 `goto` 无条件跳转,遇到指令 `end` 则本段对话结束。

```
node start
  speaker 旅店老板
  line 欢迎来到云雾镇。
  choice 打听传闻 -> rumor
  choice 直接出发 -> leave
end
```

节点有三个属性:唯一 **id**、指令列表、以及"是否入口"。

## 5.2 节点 id 规则

- 节点 id 是脚本内的**唯一标识**,`goto` / `choice` 全部靠它寻址;
- 合法 id 必须满足标识符规则(见 [04 · 4.9](04-instructions.md#49--标识符规则flag--signal--节点-id-通用)):
  - 非空;
  - 不含空白字符(空格 / Tab / 换行);
  - 不以 `#` 开头;
- 大小写敏感(`start` ≠ `Start`),字符串比较为 Ordinal。

**校验**:
- 节点 id 重复 → `节点 id 重复:'x'`(两两比对,每对重复都报一次);
- id 不合法 → 按标识符规则报错。

## 5.3 入口节点(entry)

每个脚本块可以声明**一个**入口节点,用 `entry` 指明。运行时从入口节点开始执行对话。

```
dialogue opening
  entry start        ← 入口
  node start
  ...
end
```

**规则**:
- `entry` 可选;不写也行(序列化时不输出该行);
- 但**一旦写了,目标节点必须存在**;
- 校验:
  - 缺少入口 → `缺少入口节点(entry)定义`;
  - 入口指向不存在的节点 → `入口节点 'x' 不存在`;
  - 入口 id 不合法 → 按标识符规则报错。

## 5.4 引用语义:goto / choice

`goto` 与 `choice` 的 `TargetNode` 是**强引用**——脚本里引用的目标必须在同一脚本块内真实存在:

- 目标为空 → `节点 'x' 的指令缺少目标节点`;
- 目标不存在 → `节点 'x' 引用了不存在的节点 'y'`;
- 目标 id 不合法 → 按标识符规则报错。

> 编辑器不会自动"补"缺失的节点;校验的作用就是让你在保存前发现断链。流程图里指向不存在目标的连线**画不出来**(渲染时直接跳过),校验报告会告诉你。

## 5.5 节点不能是空壳

每个节点至少要有一条指令:

- 节点没有任何指令 → `节点 'x' 没有任何指令`。

> 新建的节点默认是空壳;在校验通过前,记得给它加指令。

## 5.6 自动命名与重命名

- **自动命名**:编辑器新建节点时,自动生成 `node1`、`node2`…(前缀 + 递增数字,直到不重复为止);默认前缀 `node`。
- **重命名**:在编辑器里重命名节点 id 时,**所有引用会同步更新**:
  - 该节点的 id;
  - 所有指令里指向旧 id 的 `TargetNode`(`goto` / `choice`);
  - 脚本的 `EntryNodeId`(若入口是它);
  - 当前选中项(若选中的是它)。
  - 若新 id 已被占用,重命名被拒绝并返回失败。

## 5.7 粘贴节点

复制 / 粘贴节点时,粘贴出的节点 id 在原 id 后加 `-copy` 去重:冲突时依次尝试 `-copy-2`、`-copy-3`… 直到不重复。**注意:粘贴的是节点的浅拷贝语义——指令原样复制,但 `goto` / `choice` 的目标引用不会改写**(指向谁仍指向谁,不因粘贴而重定向)。

## 5.8 多 dialogue 块

一个文件可以含多个 `dialogue` 块。**编辑器只编辑首个块**:解析时全部块都进模型,但界面只暴露第一个;保存时其余块**原样写回**(不经过编辑器的序列化逻辑,保持字节语义)。

> 因此:如果你的 `.cdlg` 文件里有多段对话,请把需要编辑的那段放在文件最前面。界面不提供切换块的入口(见 [08 · 常见问题](08-faq.md))。

## 5.9 删除节点

删除节点时:

- 节点从脚本中移除;
- 若删除的是入口节点,**入口定义一并清空**(避免留下悬空入口);
- 选中项自动移到相邻节点(优先原位置的下一个)。
