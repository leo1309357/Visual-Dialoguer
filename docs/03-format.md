# 03 · 格式与语法

CDLG 是**行式、缩进敏感**的文本格式。本章给出完整语法参考,全部规则与 `VisualDialoguer.Core` 的解析器(`CdlgFormat.Parse`)一一对应。

## 3.1 块结构

一个 `.cdlg` 文件可以包含**一个或多个** `dialogue` 块。每个块是:

```
dialogue <id>          ← 脚本块开始(缩进 0)
  entry <node-id>      ← 入口节点(缩进 2,可选)
  node <node-id>       ← 节点开始(缩进 2)
    指令...            ← 指令(缩进 4)
  end                  ← 节点块结束(缩进 2)
end                    ← 脚本块结束(缩进 0)
```

| 层级 | 加权宽度 | 允许的命令 |
| --- | --- | --- |
| 0(顶层) | `indentWidth == 0` | `dialogue <id>`、`end` |
| 1(脚本块内) | `1 ≤ indentWidth ≤ 2` | `entry <id>`、`node <id>`、`end` |
| 2(节点块内) | `indentWidth ≥ 3` | 8 种指令(见 [04](04-instructions.md)) |

> **层级由"加权宽度"决定,不是由空格个数直接决定**:每个空格权重 1,每个 **Tab 权重 2**(因为 cdlg 一级缩进就是 2 空格,一个 Tab 顶一级)。所以:
>
> - 2 空格 → 层级 1;4 空格 → 层级 2;
> - 1 个 Tab → 层级 1;2 个 Tab → 层级 2;
> - 缩进宽度 **3 及以上**(无论怎么凑)一律按层级 2 处理。
>
> 空格与 Tab 可以混用,只要"加权宽度"落在正确区间。**层级错了,命令就放错了位置**,解析器会报"命令出现在 dialogue/node 块之外"。

## 3.2 语法单元

### dialogue 块

- `dialogue <id>`:开始一个脚本块,`<id>` 是该脚本的标识,缺 id 报错;
- 块内依次可以有 `entry` 与任意多个 `node`;
- 顶层 `end`:结束当前脚本块(解析器此刻清空"当前脚本/当前节点"上下文);
- 一个文件多个 `dialogue` 块依次解析,依次序列化。

### entry 与 node

- `entry <node-id>`:声明入口节点。缺 id 报错。**入口节点必须真实存在**,否则校验不过(见 [05](05-nodes.md));
- `node <node-id>`:开始一个节点。缺 id 报错;
- 层级 1 的 `end`:结束当前节点块。

### 指令行

- 层级 2 的行是一条指令;
- 指令**必须出现在节点块内**,否则报"指令 'x' 出现在 node 块之外";
- 指令末尾的 `end`:结束当前节点块(相当于"对话到这里结束")。

## 3.3 注释与空白

解析器对空白与注释非常宽容:

- **注释**:一行的正文(去掉缩进后)以 `#` 开头,整行跳过;
- **空行**:跳过;
- **BOM**:文件开头的单个 U+FEFF 字符被跳过(注意只跳一个字符,不会误吃正文);
- **换行**:`\r\n`、单独 `\r` 都会先归一化为 `\n` 再按行切分;
- **行尾空白**:每行正文会去掉行尾的空格与 Tab。

## 3.4 命令与参数的拆分

- 命令名是行首第一个空白(空格或 Tab)之前的部分;
- 参数是命令名之后、去掉首尾空白的剩余文本;
- `set` / `emit` 用**首词拆分**:第一个词是键 / 信号 id,剩余部分是值 / payload。

## 3.5 转义

指令的参数(说话人、台词、选项标签、set 值、emit payload)支持转义,序列化与解析**双向往返**:

| 转义序列 | 含义 |
| --- | --- |
| `\n` | 换行 |
| `\t` | 制表符 |
| `\r` | 回车 |
| `\\` | 反斜杠本身 |
| `\"` | 双引号 |

- **未知转义**(如 `\x`)解析时**保留反斜杠原样**(`\x` 两个字符都保留);
- 转义是**按字符**处理的,不限于特定字段——`speaker`、`line`、`choice` 标签、`set` 值、`emit` payload 都走同一套转义;
- `goto` / `choice` 的**目标节点 id**、`set` / `clear` 的**标志名**、`emit` 的**信号 id** 不转义(它们是按词切分的标识符,含空白就切碎了)。

## 3.6 choice 的选项分隔符

`choice` 指令用一个分隔符把"选项标签"与"目标节点"切开。解析器**两种写法都接受**:

```
choice 打听传闻 -> rumor     ← 首选写法(序列化时归一化为这种)
choice 打听传闻 | rumor      ← 兼容写法(解析也接受)
```

- 解析顺序:先找 `->`,找不到再找 `|`;
- 标签与目标都会 `Trim`;
- 标签与目标**都非空**才有效;
- **序列化统一输出 ` -> `**;
- 反过来,**标签本身不能包含 `->` 或 `|`**——校验器会拦住(否则保存后读不回)。

## 3.7 序列化输出规范

编辑器保存(`Ctrl+S`)时,按以下规范输出文本:

- **编码**:UTF-8,无 BOM;
- **换行**:LF(`\n`);
- **缩进**:`dialogue` 与顶层 `end` 缩进 0;`entry`、`node` 与节点块 `end` 缩进 2;指令缩进 4;
- **字段**:`speaker` / `line` / `choice` 标签 / `set` 值 / `emit` payload 均做转义;`choice` 分隔符归一化为 `->`;
- 脚本 id 为空时,序列化为 `dialogue untitled`;
- `entry` 为空时**不输出**该行;
- 指令按内存顺序逐条输出;`emit` 的 payload 为空时不输出空格与 payload。

## 3.8 完整示例

一个带注释、多节点、多指令的合法脚本:

```
# 开场对话 —— 注释可以写在任何层级
dialogue opening
  entry start
  node start
    speaker 旅店老板
    line 欢迎来到云雾镇。
    choice 打听传闻 -> rumor
    choice 直接出发 -> leave
  end
  node rumor
    line 据说古堡闹鬼。
    set rumor_heard yes
    goto leave
  end
  node leave
    line 一路小心。
    end
end
```

## 3.9 解析错误示例

| 写法 | 问题 |
| --- | --- |
| `dialogue`(缺 id) | `dialogue 缺少脚本 id` |
| `node`(缺 id) | `node 缺少节点 id` |
| 顶层出现 `entry` | `顶层命令应为 dialogue <id>,得到 'entry'` |
| `dialogue` 块内出现 `line` | `dialogue 块内命令应为 entry / node / end,得到 'line'` |
| 指令出现在节点块外 | `指令 'speaker' 出现在 node 块之外` |
| `choice 一个选项`(无分隔符) | `choice 格式应为 '<标签> -> <节点>' 或 '<标签> | <节点>'` |
| `set 只有键` | `set 格式应为 '<标志> <值>'` |
| `emit`(缺信号) | `emit 缺少信号 id` |
| `frobnicate x` | `未知节点指令 'frobnicate'` |

每条解析错误都带**行号**,格式为 `第 N 行:消息`。编辑器打开文件时,若解析出问题,状态栏会提示数量,按 `F5` 查看详情。
